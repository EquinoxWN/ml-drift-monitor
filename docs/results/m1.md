## Analyze

- **PSI misses a moderate shift.** Over 100 batches with income × 1.15, PSI ranged from 0.071 to
  0.137 (median 0.101) and never reached 0.2, while KS gave p < 1e-17 in every batch. Root cause:
  multiplying by 1.15 moves values mostly within neighbouring deciles. This is why the decision
  combines PSI with the test ([ADR 0002](../adr/0002-psi-and-significance-together.md)).
- **Tests alone over-alarm.** In the 200 stable batches, 7 batches had one feature with p < 0.01
  (7 of 1,200 feature checks, 0.58%), each with PSI at most 0.0135. With the combined rule these are
  warn, not drift.
- **Defect found while testing.** The first version of the income test assumed PSI stays below 0.1
  for that shift; it failed on a batch with PSI 0.114. The test now asserts what holds in every
  batch (KS significant, PSI below 0.2, never ok) and the spread is recorded above.

## Improve and Control

- CI runs ruff, ruff format, mypy --strict, pytest with warnings as errors, pip-audit and the demo
  on every push; the demo prints its RESULT line as a `::notice`.
- The `drift-schedule` workflow runs the scheduled job daily on the demo data and reports drift as a
  `::warning`, no drift as a `::notice`.
- The statistics are pinned to SciPy by tests, so a change in the numpy implementation that alters
  any value fails CI.
